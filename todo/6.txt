## Промт для AI-кодера (План на Фазу 6)

Привет! Мы переходим к Фазе 6: Создание конвейера импорта исторических чатов (Cold Storage & Embeddings Pipeline).
Наша цель — написать изолированный скрипт `parser.py`, который один раз обработает многолетний JSON-экспорт переписки из Telegram, склеит хаотичные сообщения в правильные сессии, получит для них векторный смысл (эмбеддинг) через локальную Ollama и запишет всё это в нашу базу данных SQLite.

Скрипт должен запускаться локально через менеджер пакетов uv: `uv run parser.py`.

Требования к логике `parser.py`:

1. Входные данные и окружение:
   - Скрипт принимает на вход файл `result.json` (официальный экспорт чата из Telegram Desktop).
   - Скрипт должен читать переменную окружения `OLLAMA_URL` (например, http://localhost:11434), чтобы отправлять запросы к локальному ИИ.

2. Инициализация таблицы в SQLite:
   - Скрипт должен подключиться к существующему файлу базы данных по пути `./db_data/history.db`.
   - Создай новую таблицу `historical_replies`, если она не существует, со следующими полями:
     - id (INTEGER PRIMARY KEY AUTOINCREMENT)
     - user_message (TEXT) — склеенный блок сообщений собеседника из прошлого
     - my_reply (TEXT) — ваш склеенный блок-ответ на это сообщение
     - embedding (BLOB) — векторное представление строки `user_message` (массив чисел типа float)

3. Алгоритм сессионизации, склейки и очистки (Хронологический парсинг):
   - Читай сообщения из JSON по порядку. Игнорируй медиа-заглушки (пустые строки), ссылки, системные сообщения и пересланные сообщения.
   - Склеивай идущие подряд сообщения ОДНОГО автора в единый текстовый блок через `\n`, если пауза между ними меньше 60 секунд.
   - Если пауза между репликами автора и собеседника больше 30 минут — это маркер закрытия старой сессии.
   - Нам нужны только пары, где шел разговор: Собеседник написал блок текста -> Вы ответили блоком текста. Каждую такую пару мы готовим к записи.

4. Получение Эмбеддингов (Векторов) через Ollama API:
   - Для каждой сформированной пары возьми текст `user_message`.
   - Сделай синхронный или асинхронный HTTP-запрос к Ollama на эндпоинт `/api/embeddings`.
   - Тело запроса: 
     {
       "model": "llama3.1:8b",
       "prompt": "<ТЕКСТ_USER_MESSAGE>"
     }
   - Из ответа достань массив чисел (вектор `embedding`). Для компактности и скорости SQLite преобразуй этот массив float в бинарный вид (BLOB) с помощью библиотеки `struct` (формат `f` на каждое число) или сохрани как строку JSON, если кодеру так проще, но BLOB эффективнее.

5. Запись в базу:
   - Сохрани `user_message`, `my_reply` и полученный `embedding` в таблицу `historical_replies`.
   - Добавь в консоль простой счетчик прогресса (например, "Обработано 100 пар..."), чтобы было видно, что скрипт не завис.

Напиши чистый, стабильный скрипт parser.py. Используй библиотеки `json`, `sqlite3`, `httpx` (или `requests`) и `struct`. Логику склейки сделай максимально надежной.

## Что нужно сделать перед запуском парсера:

   1. Убедитесь, что контейнер Ollama запущен (docker compose up -d ollama).
   2. Положите выгруженный из Telegram файл result.json в папку со скриптом.
   3. Запустите парсер на вашем ноутбуке:
   
   uv run parser.py
   
   4. Скрипт начнет читать ваш архив, отправлять запросы в Ollama за векторами и складывать пары в вашу SQLite базу в папке db_data. На процессоре Intel Ultra 7 это займет некоторое время в зависимости от размера архива, так как генерация эмбеддингов задействует DRAM.

Как только база будет успешно наполнена вашими историческими парами с векторами — пишите ваш сигнальный плюс +, и мы перейдем к Фазе 7 (Интеграция векторного поиска на лету в код юзербота).
