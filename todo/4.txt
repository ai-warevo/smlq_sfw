## Промт для AI-кодера (План на Фазу 4)

Привет! Мы переходим к Фазе 4: Интеграция с локальной Ollama. 
Наша цель — заменить эхо-ответ на генерацию текста из локальной нейросети. Пока работаем без хранения истории прошлых диалогов — передаем в ИИ только один текущий склеенный блок из Фазы 3.

Для этого нам нужно обновить конфигурацию Docker и дополнить файл `main.py`.

Шаг 1: Обновление зависимостей и Docker-окружения
1. В `pyproject.toml` (или через uv) добавь библиотеку `httpx` для асинхронных HTTP-запросов.
2. Обнови `docker-compose.yml`:
   - Добавь новый сервис `ollama` (образ `ollama/ollama:latest`).
   - Настрой для него монтирование volume (например, `ollama_data:/root/.ollama`), чтобы скачанные модели не стирались.
   - Ограничь ресурсы для контейнера `ollama` под процессор Intel (в секции deploy -> resources -> limits пропиши cpus: '6', memory: 16G), чтобы ИИ не вешал всю ОС.
   - В сервис `userbot` добавь зависимость `depends_on: - ollama` и переменную окружения `OLLAMA_URL=http://ollama:11434/v1/chat/completions` (используем нативный OpenAI-совместимый эндпоинт).

Шаг 2: Модификация логики в `main.py`
1. Добавь получение `OLLAMA_URL` из переменных окружения. Если переменная пустая, используй дефолтное значение.
2. В функции, которая срабатывает ПОСЛЕ истечения 10-секундного буфера тишины (где раньше был эхо-ответ), замени отправку эхо на асинхронный HTTP-запрос к Ollama через `httpx.AsyncClient()`.
3. Формат запроса (нативный Chat API):
   - Метод: POST
   - URL: Твой `OLLAMA_URL`
   - JSON-тело запроса:
     {
       "model": "llama3.1:8b", 
       "messages": [
         {
           "role": "system",
           "content": "Ты общаешься в Telegram. Отвечай очень коротко, в разговорном стиле, без заглавных букв и без смайликов. Используй только скобочки )"
         },
         {
           "role": "user",
           "content": "<ТУТ_СКЛЕЕННЫЙ_ТЕКСТ_ИЗ_БУФЕРА>"
         }
       ],
       "stream": false
     }
4. Получение ответа: вытащи сгенерированный текст из ответа Ollama (по пути `choices[0].message.content`).
5. Передача ответа в Фазу 2: полученный от ИИ текст отправь в существующий блок имитации присутствия (расчет длины строки -> статус typing -> отправка сообщения пользователю). Добавь обработку ошибок (try-except) на случай, если Ollama недоступна, чтобы бот не падал, а писал в логи ошибку.

Напиши обновленные файлы docker-compose.yml и main.py. Логику буферизации и таймингов ломать нельзя.

## Что нужно сделать руками на ноутбуке перед тестом:

   1. Когда AI-кодер обновит файлы, пересоберите контейнеры (так как добавилась новая библиотека httpx):
   
   docker compose up -d --build
   
   2. Теперь контейнер Ollama запущен, но внутри него еще нет самой модели. Нам нужно ее скачать. Выполните команду прямо в терминале вашего ноутбука:
   
   docker compose exec ollama ollama run llama3.1:8b
   
   * Начнется загрузка модели (~4.7 ГБ) из интернета. Как только она завершится и появится строка ввода, нажмите Ctrl+D, чтобы выйти из контейнера. Модель останется в памяти.
   3. Проверка работы: Напишите боту с другого аккаунта.
   * Бот подождет 10 секунд (пока вы допишете мысли).
      * Отправит текст в Ollama. На вашем процессоре Intel Lunar Lake генерация займет несколько секунд (DRAM выдаст нужную скорость).
      * Бот включит статус «печатает» на время, пропорциональное ответу ИИ.
      * Вы получите осмысленный ответ от нейросети в лаконичном стиле.
   
Как только проверите, что связка Python -> Ollama в Docker работает без ошибок в консоли, мы готовы переходить к Фазе 5: Сессионный контекст (База данных SQLite для долгосрочной памяти). Жду команду.
