## Промт для AI-кодера (План на Фазу 5)

Привет! Мы переходим к Фазе 5: Реализация долгосрочной сессионной памяти через SQLite.
Наша цель — заставить юзербота помнить контекст предыдущего разговора с каждым конкретным пользователем. 

Вносим изменения ТОЛЬКО в файл `main.py` и `docker-compose.yml` (для проброса объема под БД).

Шаг 1: Обновление docker-compose.yml
- В сервисе `userbot` добавь монтирование еще одной папки в volumes (например, `./db_data:/app/db_data`), чтобы файл базы данных SQLite сохранялся на жестком диске хоста и история не пропадала при перезапуске Docker.

Шаг 2: Модификация логики в `main.py`
1. Инициализация Базы Данных (SQLite):
   - При старте скрипта инициализируй подключение к базе данных по пути `/app/db_data/history.db`.
   - Создай таблицу `messages`, если она не существует, со следующими полями:
     - id (INTEGER PRIMARY KEY AUTOINCREMENT)
     - user_id (BIGINT) — ID пользователя Telegram, с которым идет чат
     - role (TEXT) — роль автора ('user' для сообщений собеседника, 'assistant' для ответов ИИ)
     - content (TEXT) — текст сообщения
     - timestamp (DATETIME DEFAULT CURRENT_TIMESTAMP)

2. Запись входящих сообщений:
   - В момент, когда 10-секундный буфер тишины из Фазы 3 УСПЕШНО дошел до конца и мы получили склеенный блок текста от пользователя, запиши этот текст в БД: `user_id`, `role='user'`, `content=склеенный_текст`.

3. Сбор контекста перед отправкой в Ollama:
   - Перед тем как делать HTTP-запрос к Ollama, сделай выборку (SELECT) из таблицы `messages` для текущего `user_id`.
   - Забери последние 10 сообщений (LIMIT 10), отсортированных по timestamp. Обрати внимание, что из базы они могут достаться в обратном порядке, поэтому перед отправкой отсортируй их хронологически (от старых к новым).
   - Сформируй массив `messages` для Chat API Ollama. Первым элементом всегда должен идти системный промт (из Фазы 4), а следом за ним — история из БД в формате:
     `{"role": row['role'], "content": row['content']}`

4. Запись ответа ИИ:
   - Как только Ollama вернула сгенерированный ответ, запиши его в БД: `user_id`, `role='assistant'`, `content=ответ_ии`.
   - Только после записи в БД передавай текст в существующую Фазу 2 (расчет задержки тайпинга и отправка).

Обеспечь потокобезопасное или корректное асинхронное взаимодействие с SQLite (библиотека sqlite3 встроена в Python, но помни, что вызовы к ней блокирующие, поэтому операции с БД желательно выполнять через `asyncio.to_thread` или использовать библиотеку `aiosqlite`, если это упростит асинхронный код).
